Arquitetura

Camadas com propósito.
Nenhuma opcional.

Cada componente DSS segue uma arquitetura de 4 camadas obrigatórias. A estrutura garante separação de responsabilidades, testabilidade e manutenibilidade previsíveis.

CSS Cascade Layers — Isolamento

DSS — unlayered (sem @layer)
VENCE TUDO
@layer quasar { } — CSS do Quasar
CONTIDO
@layer vendor { } — CSS de terceiros
CONTIDO

DSS não usa !important para vencer terceiros — a ausência de @layer garante precedência por spec CSS.

13 Princípios Fundamentais

1
Token First
Nenhum valor hardcoded — sempre var(--dss-*)
2
Sass Module System
@use / @forward obrigatório · @import proibido
3
Cores via Classes
Aplicação via bg-*, text-* — nunca SCSS hardcoded
4
4 Camadas Obrigatórias
Nenhuma camada pode ser omitida — mesmo com pouco conteúdo
5
WCAG 2.1 AA
Acessibilidade não é feature — é pré-requisito de existência
8
Pseudo-elementos Reservados
::before = touch target (WCAG 2.5.5) · ::after = efeitos visuais
12
CSS como Fonte de Verdade
CSS → meta.json → DSS_REFERENCIA_VISUAL. Nenhuma cadeia inversa.
13
Cascade Layers
CSS de terceiros isolado em @layer · DSS nunca dentro

Acessibilidade

WCAG 2.1 AA.
Embutido, não adicionado.

Acessibilidade não é uma feature do DSS — é um pré-requisito de conformidade. Cada componente que recebe o Selo DSS foi validado contra os critérios WCAG 2.1 nível AA.

✓
Touch Target ≥ 44px
Critério 2.5.5 — ::before reservado exclusivamente para área de toque
✓
Focus Ring Visível
Mixin dss-focus-ring() com tokens --dss-focus-ring-* em todos os contextos
✓
Navegação por Teclado
Tab, Enter, Space, Arrow keys em todos os componentes interativos
✓
prefers-reduced-motion
Mixin dss-transition() respeita preferências de animação automaticamente
✓
High Contrast Mode
@media (forced-colors: active) implementado em todos os estados (L4)
✓
ARIA Semântico
role, aria-label, aria-disabled, aria-live, aria-expanded — nenhuma inferência
✓
Contraste WCAG
Função Sass dss-contrast-ratio() valida em tempo de compilação
✓
Skip Links
Mixin dss-skip-link() disponível para navegação acessível entre landmarks

Pseudo-elementos reservados

Uma convenção normativa que garante conformidade WCAG 2.5.5 sem conflitos com efeitos visuais:

::before
RESERVADO — touch target exclusivamente (WCAG 2.5.5)
::after
Efeitos visuais — hover overlay, active, selected
Governança

Qualidade rastreável.
Não negociável.

O DSS opera com um modelo formal de certificação. Nenhum componente recebe o Selo DSS v2.2 sem passar pelos três gates: estrutural, técnico e documental.

🏗️

Gate Estrutural

✓ 4 camadas em completude
✓ Entry Point Wrapper (re-export puro)
✓ Orchestrador SCSS L2→L3→L4
✓ Barrel export (index.js) completo
✓ dss.meta.json com campos obrigatórios
⚙️

Gate Técnico

✓ Zero valores hardcoded (Token First)
✓ Cores via classes utilitárias
✓ hover, focus, active, disabled
✓ WCAG 2.1 AA validado
✓ SCSS compila sem erros
📋

Gate Documental

✓ Tokens listados com nomes exatos
✓ README completo (mín. 3 exemplos)
✓ Template 13.1 (13 seções)
✓ API Reference atualizada
✓ Arquivo de testes com cobertura

Possibilidades de Evolução

Um sistema vivo.
Projetado para crescer.

O DSS v2.2 é uma base sólida — token-first, testada, governada e acessível. As próximas fronteiras ampliam o alcance sem comprometer o que foi construído.

🎨
Figma MCP Sync
Sincronização bidirecional Figma ↔ DSS via MCP. Tokens e componentes em código e design sempre alinhados.
📖
Storybook Automatizado
Portal de documentação interativo gerado a partir de dss.meta.json — zero escrita manual de stories.
👁️
Testes Visuais (VRT)
Visual Regression Testing com Chromatic ou Percy — detecta regressões de pixel em PRs automaticamente.
♿
A11y no Pipeline CI
axe-core integrado nos PRs — nenhum componente chega à main com violação de acessibilidade.
🏷️
Design Tokens W3C (DTCG)
Migração para o formato JSON W3C Design Token spec — interoperabilidade nativa com Figma, Style Dictionary e ferramentas de mercado.
🌙
Temas Expandidos
Alto contraste nativo, modo daltonismo (deuteranopia, protanopia), temas de terceiros via API de tokens.
📊
Telemetria de Uso
Analytics de componentes em produção — quais são mais usados, quais props são ignoradas, aonde há fricção.
🤖
AI Governance Expandida
Validação automática de conformidade por LLM via MCP — auditorias em tempo real durante o desenvolvimento.
📱
Fase 3 — Composições Complexas
Componentes de alta composição, patterns de página completos e templates prontos para domínios específicos (saneamento, gestão).
