# Pré-prompt de Criação de Componente DSS: DssBreadcrumbs

## 1. Classificação e Contexto
- **Nome do Componente:** `DssBreadcrumbs`
- **Família:** Navegação e Estrutura de Conteúdo
- **Nível de Composição:** Nível 2 (Composição de Primeiro Grau) - Este componente atua como um container orquestrador, encapsulando e gerenciando a disposição de componentes de Nível 1 (`DssBreadcrumbsEl`). Sua principal função é estabelecer o layout e o espaçamento, delegando a interatividade e o estilo individual aos seus filhos.
- **Golden Reference:** `DssChip` (para componentes interativos e containers de elementos interativos). Embora `DssBreadcrumbs` seja um container, ele orquestra elementos interativos, tornando `DssChip` uma referência mais apropriada para o comportamento interativo esperado de seus filhos.
- **Golden Context:** `DssCard` ou Layouts de Página (container pai mais comum) - O `DssBreadcrumbs` é frequentemente utilizado no cabeçalho de páginas ou dentro de cards para indicar a localização atual do usuário dentro de uma hierarquia de navegação.
- **Componente Quasar Base:** `QBreadcrumbs` - O componente DSS estende e aprimora o `QBreadcrumbs` nativo, aplicando a governança de design system e corrigindo inconsistências de estilo e acessibilidade.
- **Dependência Direta:** `DssBreadcrumbsEl` (Nível 1) - O `DssBreadcrumbs` é projetado para funcionar exclusivamente com `DssBreadcrumbsEl` como seus filhos diretos, garantindo a aplicação consistente de tokens e comportamentos.

## 2. Riscos Arquiteturais e Gates de Responsabilidade

### 2.1. Risco Principal: Separadores, Alinhamento e Coerência Visual
O `QBreadcrumbs` nativo injeta separadores (ícones ou texto) entre os elementos filhos. O risco é que esses separadores não respeitem a tipografia, as cores e o espaçamento definidos pelo Design System Sansys (DSS), ou que o alinhamento vertical entre os separadores e os itens (`DssBreadcrumbsEl`) fique quebrado, comprometendo a coesão visual.
**Mitigação:** O `DssBreadcrumbs` deve sobrescrever os estilos dos separadores nativos (`.q-breadcrumbs__separator`) usando tokens DSS para tipografia (`--dss-font-size-sm`, `--dss-line-height-sm`) e cores (`--dss-text-subtle`). O alinhamento vertical deve ser garantido via flexbox (`align-items: center`) no container principal do `DssBreadcrumbs`.

### 2.2. Gate de Responsabilidade v2.4: Orquestração de Layout
Como componente de Nível 2, o `DssBreadcrumbs` é um **container orquestrador**. Ele **não deve** gerenciar estados interativos (`:hover`, `:focus-visible`, `:active`) — essa responsabilidade é exclusiva dos filhos (`DssBreadcrumbsEl`). A responsabilidade primária do `DssBreadcrumbs` é gerenciar o layout (utilizando flexbox para distribuição horizontal), o espaçamento entre os itens (gap) e a renderização consistente dos separadores, garantindo que a estrutura geral do breadcrumb esteja em conformidade com o DSS.

### 2.3. Gate de Composição v2.4: Encapsulamento Estrito
O componente deve ser um wrapper direto do `<q-breadcrumbs>`. O slot `default` deve aceitar **apenas** componentes `DssBreadcrumbsEl`. O uso de HTML nativo, outros componentes Quasar ou componentes DSS não-`DssBreadcrumbsEl` dentro do slot viola a governança da Fase 2, que exige um encapsulamento estrito para garantir a previsibilidade e a manutenibilidade do componente.

## 3. Mapeamento de API (Props e Eventos)

### 3.1. Props Expostas (Permitidas) e Detalhamento
- `separator` (String): Define o caractere ou string a ser usado como separador entre os itens do breadcrumb (ex: `/`, `>`). Este prop permite flexibilidade na representação visual dos caminhos de navegação.
- `separator-color` (String): Controla a cor do separador. Deve mapear para tokens de cor de texto do DSS, como `--dss-text-subtle` ou `--dss-text-hub`, garantindo que a cor do separador esteja alinhada com a paleta do sistema.
- `gutter` (String): Especifica o espaçamento horizontal entre os itens do breadcrumb. Deve mapear para tokens de espaçamento do DSS (ex: `sm` -> `--dss-spacing-2`, `md` -> `--dss-spacing-3`, `lg` -> `--dss-spacing-4`), garantindo um espaçamento consistente.
- `align` (String): Define o alinhamento horizontal dos itens dentro do container do breadcrumb (`left`, `center`, `right`, `between`, `around`). Este prop é crucial para o posicionamento do componente em diferentes layouts.

### 3.2. Props Bloqueadas (Governança DSS) e Justificativa
- `active-color`: Bloqueado. A cor do item ativo é governada exclusivamente pelo `DssBreadcrumbsEl` para manter a responsabilidade de estilo em nível de componente atômico e evitar conflitos de estilo.
- `separator-class`: Bloqueado. Os estilos do separador são governados diretamente pelo CSS interno do componente `DssBreadcrumbs` para garantir a aplicação consistente dos tokens DSS e evitar que estilos externos quebrem a coerência visual.

## 4. Governança de Tokens e CSS

O `DssBreadcrumbs` deve utilizar os seguintes tokens para garantir a aderência ao Design System Sansys:
- **Tipografia (Separadores):** `--dss-font-size-sm` (tamanho da fonte pequena) e `--dss-line-height-sm` (altura da linha pequena). Esta combinação garante que os separadores sejam discretos, mas legíveis, e que o alinhamento vertical com o texto dos itens seja mantido. É crucial usar `--dss-line-height-sm` e **não** `--dss-line-height-md`, conforme confirmado em compilações reais e testes de regressão do componente.
- **Cores (Separadores):** `--dss-text-subtle` (padrão para texto de menor ênfase); `--dss-text-disabled` quando o breadcrumb inteiro estiver desabilitado, indicando um estado inativo. Para cores de brand, podem ser utilizados `--dss-text-hub`, `--dss-text-water`, `--dss-text-waste` quando especificado via `separator-color` prop.
- **Espaçamento (Gutter):** `--dss-spacing-2` (para `sm`), `--dss-spacing-3` (para `md`), `--dss-spacing-4` (para `lg`). Estes tokens garantem um espaçamento horizontal consistente entre os itens do breadcrumb, alinhado com a escala de espaçamento do DSS.
- **Tokens Fantasmas Corrigidos:**
    - `--dss-spacing-4` substituído por `--dss-spacing-4`
    - `--dss-text-subtle` substituído por `--dss-text-subtle`
    - `outline: 2px solid white` removido ou substituído por `outline: 2px solid white` (se aplicável ao contexto de foco, embora a responsabilidade de foco seja dos filhos).
    - `--dss-action-hub` substituído por `--dss-action-hub`
    - `--dss-action-hub-surface` substituído por `--dss-action-hub-surface`

> **Nota:** `--dss-text-disabled` é um token de estado formalizado no catálogo DSS (seção 4.6 do `DSS_TOKEN_REFERENCE.md`). Valor light: `var(--dss-gray-400)` (#d4d4d4); valor dark: `var(--dss-gray-600)` (#737373). Distinto de `--dss-text-subtle` (texto ativo de menor ênfase) e `--dss-text-hint` (placeholder para inputs).

## 5. Acessibilidade e Estados

- **Role:** O `QBreadcrumbs` gerencia o `role="navigation"` e `aria-label="Breadcrumb"` nativamente, o que é fundamental para a identificação semântica do componente por tecnologias assistivas. O `DssBreadcrumbs` deve preservar e, se necessário, aprimorar essas propriedades.
- **Aria-current:** O `DssBreadcrumbs` não gerencia o `aria-current` diretamente. Esta propriedade deve ser passada como prop para o último `DssBreadcrumbsEl` da lista, indicando o item atualmente ativo na navegação. Isso garante que leitores de tela informem corretamente a posição do usuário.
- **Separadores:** Os separadores injetados pelo Quasar recebem `aria-hidden="true"` nativamente. Esta é uma prática correta para acessibilidade, pois evita que leitores de tela leiam os separadores como parte do conteúdo navegável, reduzindo a redundância e melhorando a experiência do usuário.
- **Estados de Foco e Interação:** Embora o `DssBreadcrumbs` não gerencie estados interativos diretamente, ele deve garantir que os `DssBreadcrumbsEl` filhos possam expor e gerenciar seus próprios estados de `:hover`, `:focus-visible` e `:active` de forma acessível, com indicadores visuais claros e contrastantes.

## 6. Cenários de Uso Obrigatórios (Exemplos)

O arquivo `DssBreadcrumbs.example.vue` deve cobrir os seguintes cenários, demonstrando a versatilidade e a conformidade do componente:
1. **Básico:** Trilha de navegação simples com três itens e separador padrão (`/`), mostrando a estrutura fundamental do componente.
2. **Separador Customizado:** Uso da prop `separator` com um caractere diferente (ex: `>`) ou uma string mais complexa, demonstrando a flexibilidade na personalização do separador.
3. **Alinhamento:** Demonstração da prop `align` com valores como `center` ou `right`, ilustrando como o breadcrumb se adapta a diferentes requisitos de layout.
4. **Com Ícones:** Trilha onde os itens (`DssBreadcrumbsEl`) possuem ícones antes ou depois do texto, mostrando a capacidade de enriquecer a navegação visualmente.
5. **Breadcrumb Longo com Truncamento:** Um cenário com muitos itens para verificar como o componente lida com o espaço limitado, idealmente com algum mecanismo de truncamento ou rolagem horizontal (se aplicável ao `QBreadcrumbs` base).
6. **Breadcrumb Desabilitado:** Demonstração do componente em um estado desabilitado, onde todos os itens e separadores utilizam o token `--dss-text-disabled`.

## 7. Exceções aos Gates v2.4

### EXC-01: Seletor de Classe Interna do Quasar (Gate de Composição)
- **Regra Violada:** Regra 1 (Proibição de seletores CSS que referenciam classes internas do Quasar).
- **Justificativa:** O `QBreadcrumbs` injeta elementos DOM para os separadores com a classe `.q-breadcrumbs__separator`. Para aplicar a tipografia e cor do DSS a esses separadores, é estritamente necessário usar o seletor `.dss-breadcrumbs .q-breadcrumbs__separator`. Esta é uma exceção formal e documentada, seguindo o precedente de componentes orquestradores que precisam estilizar elementos internos de componentes base de terceiros para garantir a conformidade visual com o Design System.

## 8. Superfície de Playground

A superfície de playground para `DssBreadcrumbs` deve demonstrar a integração e o comportamento do componente em cenários realistas, focando na sua função como orquestrador de layout e espaçamento para `DssBreadcrumbsEl`. O playground deve ser interativo e permitir a manipulação das propriedades essenciais do componente, facilitando a visualização de diferentes configurações e estados.

### 8.1. Controles Obrigatórios

Os seguintes controles devem estar disponíveis no playground para permitir a manipulação e visualização das propriedades essenciais do `DssBreadcrumbs`, garantindo que os desenvolvedores possam testar todas as variações e comportamentos:

- **`separator` (String):** Um campo de texto para definir o caractere ou string do separador (ex: `/`, `>`). Este controle permite testar diferentes estilos de separação.
- **`separator-color` (Dropdown):** Um seletor para escolher a cor do separador a partir dos tokens de texto do DSS (ex: `--dss-text-subtle`, `--dss-text-hub`, `--dss-text-water`, `--dss-text-waste`). Isso demonstra a aplicação dos tokens de brand e neutros.
- **`gutter` (Dropdown):** Um seletor para definir o espaçamento entre os itens do breadcrumb, utilizando tokens de espaçamento do DSS (ex: `--dss-spacing-2`, `--dss-spacing-3`, `--dss-spacing-4`). Essencial para verificar o alinhamento e a densidade do layout.
- **`align` (Dropdown):** Um seletor para controlar o alinhamento horizontal dos itens (ex: `left`, `center`, `right`, `between`, `around`). Permite testar o comportamento do componente em diferentes contextos de layout.
- **`items` (Array de Objetos):** Um editor de array para adicionar, remover e modificar os itens do breadcrumb dinamicamente. Cada item deve permitir a configuração de:
    - `label` (String): O texto exibido no item do breadcrumb.
    - `to` (String): O caminho da rota para o item (simulando navegação), demonstrando a funcionalidade de link.
    - `icon` (String, Opcional): O nome do ícone Quasar a ser exibido ao lado do label, para cenários com ícones.
    - `active` (Boolean): Indica se o item é o ativo (`aria-current`), crucial para testar a acessibilidade e o estilo do item atual.

### 8.2. Composite Logic (Concreta, Não Genérica)

A lógica de composição no playground deve refletir como o `DssBreadcrumbs` interage com seus filhos `DssBreadcrumbsEl` e como ele gerencia o layout. Exemplos de lógica a serem demonstrados:

- **Renderização Condicional de Separadores:** O `DssBreadcrumbs` deve renderizar separadores apenas entre os itens, e não antes do primeiro ou depois do último. A lógica deve garantir que, ao adicionar ou remover itens, os separadores sejam ajustados corretamente.
- **Propagação de Props para Filhos:** A prop `separator-color` do `DssBreadcrumbs` deve influenciar a cor dos separadores, enquanto outras props de estilo (como `active-color` ou `text-color`) devem ser gerenciadas pelos `DssBreadcrumbsEl` individualmente. O playground deve ilustrar essa divisão de responsabilidades.
- **Gerenciamento de Espaçamento:** A prop `gutter` deve aplicar o espaçamento correto entre os `DssBreadcrumbsEl` e os separadores, utilizando as classes CSS ou estilos inline gerados a partir dos tokens DSS.
- **Manipulação de Slots:** A lógica deve garantir que apenas `DssBreadcrumbsEl` sejam aceitos no slot padrão, e que qualquer outro tipo de conteúdo seja ignorado ou resulte em um aviso no console, reforçando o Gate de Composição.
