"""# Pré-prompt: DssPopupProxy

## 1. CLASSIFICAÇÃO E CONTEXTO

### Golden Reference
DssChip

### Golden Context
DssMenu

### Justificativa do Golden Context
DssMenu é o overlay de navegação mais próximo do DssPopupProxy: ambos teleportam para `<body>`, usam QMenu como motor (modo desktop do DssPopupProxy), aplicam os mesmos tokens de superfície (`--dss-surface-default`, `--dss-elevation-3`, `--dss-radius-md`), e seguem o padrão de CSS global (sem `<style scoped>`). A diferença central é que DssPopupProxy adiciona a camada de decisão responsiva (QMenu vs QDialog via `breakpoint`). A conformidade do DssPopupProxy deve ser auditada em relação ao DssMenu como baseline específico.

### Justificativa
A necessidade de um componente DssPopupProxy surge da complexidade inerente ao gerenciamento de popups em aplicações web. A padronização de popups é crucial para a coesão do Design System, evitando implementações inconsistentes e problemas de acessibilidade. Este componente encapsula a lógica de interação, posicionamento e acessibilidade, permitindo que os desenvolvedores se concentrem no conteúdo do popup, enquanto o DSS garante a experiência do usuário e a conformidade técnica. A reusabilidade e a manutenibilidade são significativamente melhoradas, pois a lógica de popup é centralizada e testada, reduzindo a probabilidade de erros e inconsistências em toda a aplicação. Além disso, o DssPopupProxy facilita a implementação de diretrizes de design e acessibilidade, garantindo que todos os popups no sistema sigam os mesmos padrões.

## 2. RISCOS ARQUITETURAIS E GATES

### Riscos Arquiteturais
- **Performance**: Múltiplos popups abertos simultaneamente ou popups com conteúdo complexo podem impactar a performance da renderização, especialmente em dispositivos com recursos limitados. A otimização do ciclo de vida do popup e a renderização condicional do conteúdo são cruciais para mitigar este risco.
- **Acessibilidade**: Falha em gerenciar corretamente o foco, atributos ARIA e navegação por teclado pode tornar o componente inacessível para usuários com deficiência. A implementação rigorosa das diretrizes WCAG é fundamental.
- **Conflitos de Posicionamento**: Em cenários complexos (scroll, redimensionamento, popups aninhados), o posicionamento pode falhar ou causar reflows indesejados, resultando em uma experiência de usuário quebrada. A utilização de bibliotecas de posicionamento robustas e testadas é recomendada.
- **Acoplamento**: Risco de acoplamento excessivo com componentes Quasar subjacentes, dificultando futuras migrações ou customizações. A abstração da API do Quasar e a exposição de uma interface agnóstica ao framework são importantes para a longevidade do componente.
- **Z-index**: Gerenciamento inadequado do z-index pode fazer com que popups sejam renderizados abaixo de outros elementos, tornando-os invisíveis ou inacessíveis. Uma estratégia de z-index global e bem definida é necessária.

### Gates
- **Revisão de Design**: Validação da experiência do usuário e aderência aos padrões visuais do DSS por uma equipe de design. Isso inclui a revisão de fluxos de interação, estados visuais e feedback do usuário.
- **Revisão de Código**: Garantia de boas práticas de Vue.js/Quasar, modularidade, manutenibilidade e legibilidade do código por pares. A cobertura de testes unitários e de integração também é verificada.
- **Auditoria de Acessibilidade**: Testes rigorosos de teclado, leitores de tela e conformidade com WCAG por especialistas em acessibilidade. Isso envolve testes manuais e automatizados para identificar e corrigir barreiras de acessibilidade.
- **Testes de Performance**: Avaliação do impacto em cenários de uso intensivo, incluindo testes de carga e estresse. Métricas como tempo de carregamento, FPS e uso de memória são monitoradas.
- **Documentação Completa**: Garantia de que a documentação do componente está atualizada, clara e abrangente, incluindo exemplos de uso, diretrizes de API e considerações de acessibilidade.

**defineExpose (EXC-Expose-01)**: `show(evt?)`, `hide(evt?)`, `toggle(evt?)`, `currentComponent` — delegados ao `ref` interno do QPopupProxy.

## 4. GOVERNANÇA DE TOKENS E CSS

O DssPopupProxy utilizará os tokens de design do DSS para espaçamento, raio de borda, cores de superfície e durações de transição, garantindo a consistência visual e a aderência à identidade da marca. A gestão de tokens é crucial para manter a escalabilidade e a manutenibilidade do Design System.

**Tokens utilizados (implementação canônica)**:
- **Cor de Superfície**: `--dss-surface-default` — background do painel popup (menu e dialog)
- **Sombra**: `--dss-elevation-3` — sombra do painel em modo menu (`!important` — EXC-01)
- **Raio de Borda**: `--dss-radius-md` — border-radius do painel
- **Tipografia**: `--dss-font-family-sans` — fonte do conteúdo interno
- **Cor de Texto**: `--dss-text-body` — cor padrão do conteúdo
- **Borda Dark Mode**: `--dss-border-width-thin` + `--dss-gray-200`
- **Borda High Contrast**: `--dss-border-width-md`
- **Z-index**: Gerenciado pelo Quasar via QMenu/QDialog — DssPopupProxy NÃO altera z-index.

**Brand**: Delegado aos componentes filhos via slot (DssList, DssItem, DssCard). DssPopupProxy não aplica brand diretamente.

**Tokens Proibidos (não existem no DSS — usar alternativas)**:
- `--dss-shadow-2` → Use `--dss-elevation-3` (sombra de overlay — nível 3)
- `--dss-shadow-md` → Use `--dss-elevation-3` (mesma razão)
- `--dss-spacing-4` → Use `--dss-padding-4` (padding) ou `--dss-gap-2` (gap)
- `--dss-action-hub` → Use `--dss-hub-600` (ação primária Hub)
- `--dss-action-water` → Use `--dss-water-600` (ação primária Water)
- `--dss-action-waste` → Use `--dss-waste-600` (ação primária Waste)
- `--dss-action-hub-surface` → Use `--dss-hub-100` (superfície Hub)
- `--dss-text-subtle` → Verificar catálogo; usar `--dss-text-secondary` se disponível
- `--dss-duration-250` → Verificar catálogo; usar via `transition: var(--dss-transition-*)` se disponível
- Valores hardcoded de px, rem, hex, rgb → Sempre `var(--dss-*)`

## 5. ACESSIBILIDADE E ESTADOS

### Acessibilidade
- **Foco**: O foco será gerenciado para mover-se para o conteúdo do popup quando aberto e retornar ao elemento que o acionou quando fechado (a menos que `noRefocus` seja `true`). Isso garante uma navegação por teclado intuitiva e eficiente.
- **ARIA**: Atributos `role="dialog"`, `aria-modal="true"`, `aria-labelledby` e `aria-describedby` serão aplicados para fornecer semântica adequada a leitores de tela. O `aria-live` pode ser usado para anunciar mudanças de estado importantes.
- **Navegação por Teclado**: Suporte completo para navegação por teclado, incluindo `Tab` para mover o foco entre elementos interativos dentro do popup, `Shift + Tab` para navegação reversa e `Escape` para fechar o popup.
- **Contraste de Cores**: Garantia de que o contraste de cores do texto e dos elementos interativos dentro do popup atenda aos requisitos mínimos do WCAG 2.1 AA.

### Estados
- **Aberto/Fechado**: Controlado pela propriedade `v-model:open`. O estado `aberto` exibe o popup, enquanto o estado `fechado` o oculta.
- **Focado**: O popup pode estar em um estado focado quando o usuário interage com ele via teclado ou mouse. O foco visual é importante para a acessibilidade.
- **Posicionado**: O estado de posicionamento do popup é dinâmico e depende do `target`, `anchor`, `self` e `offset`. O componente recalcula a posição em resposta a eventos de scroll e redimensionamento.

## 6. COMPORTAMENTO E INTERAÇÕES

### Comportamento Padrão
- **Abertura/Fechamento**: O popup é aberto quando o `v-model:open` é `true` e fechado quando é `false`. Pode ser acionado por clique no `target` ou programaticamente.
- **Posicionamento Dinâmico**: O popup ajusta sua posição automaticamente em relação ao `target` e à janela de visualização, evitando que ele saia da tela.
- **Fechamento ao Clicar Fora**: Por padrão, o popup fecha quando o usuário clica fora de sua área, a menos que a propriedade `persistent` seja `true`.
- **Fechamento ao Pressionar ESC**: O popup fecha quando a tecla `Escape` é pressionada, a menos que a propriedade `persistent` seja `true`.

### Interações
- **Clique no Target**: Um clique no elemento `target` pode alternar o estado de abertura/fechamento do popup.
- **Interação com Conteúdo**: O conteúdo dentro do popup pode conter elementos interativos (botões, links, formulários) que respondem a eventos do usuário.
- **Eventos de Scroll/Redimensionamento**: O popup reage a eventos de scroll e redimensionamento da janela, ajustando sua posição para permanecer visível e corretamente alinhado.

## 8. SUPERFÍCIE DE PLAYGROUND

### Controles Obrigatórios
- **`v-model:open` (Boolean)**: Para controlar a visibilidade do DssPopupProxy. Deve permitir alternar entre `true` e `false`.
- **`target` (String | Ref)**: Um campo de texto ou seletor para definir o elemento que aciona o popup. Ex: `#my-button` ou uma referência Vue.
- **`anchor` (String)**: Um dropdown com opções como `top start`, `top middle`, `top end`, `bottom start`, `bottom middle`, `bottom end`, `left top`, `left middle`, `left bottom`, `right top`, `right middle`, `right bottom`.
- **`self` (String)**: Um dropdown com as mesmas opções de `anchor` para definir o ponto de ancoragem do próprio popup.
- **`offset` (Array<Number>)**: Dois campos numéricos para `x` e `y` para ajustar o deslocamento do popup. Ex: `[10, 10]`.
- **`persistent` (Boolean)**: Um checkbox para ativar/desativar o fechamento do popup ao clicar fora ou pressionar ESC.
- **`autoClose` (Boolean)**: Um checkbox para ativar/desativar o fechamento do popup ao clicar em seu conteúdo.
- **`noFocus` (Boolean)**: Um checkbox para impedir que o popup capture o foco.
- **`noRefocus` (Boolean)**: Um checkbox para impedir que o foco retorne ao target.
- **Conteúdo do Slot Padrão (Slot)**: Uma área de texto para inserir conteúdo HTML/Vue arbitrário que será exibido dentro do popup. Ex: `<DssButton label="Ação" color="hub" />`.

### Composite Logic (concreta, não genérica)
1. **Popup de Confirmação de Exclusão**: Um DssPopupProxy que exibe um DssCard com uma mensagem de confirmação ("Tem certeza que deseja excluir este item?") e dois botões: "Cancelar" (DssButton com `color="water"`) e "Excluir" (DssButton com `color="waste"`). O popup deve ser `persistent` para exigir uma decisão do usuário.
2. **Menu de Opções de Usuário**: Um DssPopupProxy acionado por um DssAvatar que, ao ser clicado, exibe um DssList com opções como "Meu Perfil", "Configurações" e "Sair". O popup deve ter `autoClose` para fechar após a seleção de uma opção.
3. **Tooltip de Informação**: Um DssPopupProxy acionado por um DssIcon (`info`) que, ao passar o mouse, exibe um DssCard pequeno com uma breve descrição ("Este campo é obrigatório."). O popup deve ter `noFocus` e `noRefocus` para não interferir na navegação.
4. **Seletor de Data Personalizado**: Um DssPopupProxy que, ao ser acionado por um DssInput, exibe um componente de calendário customizado. O popup deve ter `anchor="bottom start"` e `self="top start"` para se alinhar corretamente ao input.
